# Auto power off, STOP and wake in a few seconds: APO enabled by the EEPROM byte 0x16 = 0, the APO countdown put 3 s before
# its expiry, the meter powers down into STOP (PE9 low), a dial change (v -> mV) wakes it and the power-on window runs again
# (a dial line, not a key, so that the wake event has no meaning inside the power-on window: v2.05, which leaves its WFE at
# once in the emulator (NF-05 below), and the port then run the same window and the same mode apply).
source analysis/rotary.md section 4 power-off path (counter 0x20000230 reloaded with 0x708 = 1800 when minmax_state == 0 (0x0800ED26), decremented once per NJU6350 second (0x200080D4 set by FUN_080100C4) only while 0x20008039 == 0; enter_stop_and_reinit clears PE9)
source v2.05 main 0x08024CAE..0x08024CDC: with 0x20008039, minmax_state and 0x20007FE1 all 0 the u16 0x20000230 is decremented (strh 0x08024CCE) and at 0 the power-off request 0x2000803A = 1 is set (0x08024CDC); the 60 s warning starts at 60 (0x08024CEC), so a start value of 3 gives no warning beeps
source analysis/keys_setup.md section 4 item 2 (0x20008039 is loaded from EEPROM 0x16; 0 = APO on, "APOoN")
source analysis/rotary.md section 4 (FUN_0801C61C arms EXTI on the key and dial lines; wake runs FUN_0800EA3A again; the dial is latched with the v2.05 rule and its mode applied after the window)
source firmware/DESIGN.md 3.6 NF-05: v2.05 enters STOP with a single WFE (0x080207F6) and returns on any event, so whether it is still in STOP when MODE is pressed depends on the event register; no assertion is made between the power-down and the dial change
